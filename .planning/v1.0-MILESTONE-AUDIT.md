## Cross-Phase Integration

### Blocking gap: exact-date vacation collision

The next-payment selector chooses a single event with `schedule > bonus > vacation` priority. The downstream forecast only adds vacation gross when the chosen kind is `vacation`. Therefore:

- Salary/advance + vacation on the same date displays and taxes only salary/advance.
- Bonus + vacation on the same date displays and taxes only the bonus.
- The vacation payment disappears after that date because the product exposes only one next-payment slot.
- The annual summary still includes the vacation independently, so annual totals disagree with the previously shown next-payment forecast.

Required correction: represent same-date income as one composed payment event, include every colliding component in gross and cumulative tax, and render the vacation disclosure whenever vacation pay is part of the composition. Add regression tests for schedule+vacation and bonus+vacation exact-date cases.

The regression tests now exist in `src/app/actions/forecast.test.ts` and fail for exactly these two cases. The current full run is 353/355 passing: schedule+vacation returns schedule-only gross/tax with no `vacationId`, and bonus+vacation returns bonus-only gross/tax with no `vacationId`.
