## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label / Heading | 14–18px (text-sm, text-lg) | 600 (semibold) | 1.2 |
| Display | 24–32px (text-2xl, text-3xl) | 600 (semibold) | 1.2 |

**Font Weight Scale (2 total):**
- 400 (regular) — body text only
- 600 (semibold) — all labels, headings, interactive elements, and display

**Tailwind classes:**
- Body: `text-sm` (14px), no explicit font-weight → 400 (regular)
- Label: `text-sm font-medium` or `text-sm font-semibold` → 14px, 500–600 weight
- Heading: `text-lg font-semibold` → 18px, 600 weight
- Display: `text-2xl font-semibold` (24px) or `text-3xl font-semibold` (32px), 600 weight

**Rationale:**
- 14px body is readable on mobile (Phase 1 requirement: PWA on iPhone).
- 1.5 line-height on body ensures readability; 1.2 on headings matches Russian typography conventions.
- Semibold (600) used for all interactive labels and headings to create clear visual hierarchy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white (#ffffff) light / #0a0a0a dark | Page background, card backgrounds (light/dark mode toggle via `prefers-color-scheme`) |
| Secondary (30%) | zinc-100 light / zinc-900 dark | Card borders, disabled states, secondary text |
| Accent (10%) | zinc-900 (actions) / red-600 (destructive) | Primary CTA buttons, form labels, destructive actions only |
| Destructive | red-600 | Error messages, delete confirmations, validation feedback |
| Supporting | zinc-400, zinc-500, zinc-600 | Secondary text, hints, disabled states |

**Color-specific rules:**

1. **Primary CTA (Add Vacation button, Save button):** `bg-zinc-900 text-white rounded-lg px-4 py-2 text-sm font-medium` — matches Phase 1–2 buttons.
2. **Secondary/Cancel button:** `border border-zinc-300 text-zinc-900 rounded-lg px-4 py-2 text-sm font-medium` — outlined style.
3. **Destructive button (Delete):** `bg-red-600 text-white rounded-lg px-4 py-2 text-sm font-medium` or text-only `text-red-700 underline` — only for delete actions, requires confirmation.
4. **Form labels:** `text-sm font-medium` in zinc-900 (light) / zinc-100 (dark).
5. **Form inputs:** `rounded border border-zinc-300 px-3 py-2` — matches Phase 1–2 salary/bonus forms.
6. **Error text:** `text-sm text-red-600` — matches Phase 1–2 validation errors.
7. **Placeholder/hint text:** `text-sm text-zinc-500` or `text-xs text-zinc-400`.
8. **Card border:** `border border-zinc-200` (light) / `border-zinc-800` (dark).
9. **Section divider:** `border-t border-zinc-200` or `border-b border-zinc-200`.
10. **D-V12 inline caption (simplified-calculation disclaimer):** `text-xs text-zinc-500` — non-intrusive, placed directly adjacent to the calculated отпускные amount.

**Dark mode support:**
- Light mode: CSS `@media (prefers-color-scheme: light)` (default in globals.css)
- Dark mode: CSS `@media (prefers-color-scheme: dark)` (default applies dark values)
- No forced dark mode; iOS Safari respects system setting.

**Accent reserved for:**
- Primary CTA buttons ("Добавить отпуск", "Сохранить", "Подтвердить")
- Form field labels (required/descriptive text)
- Active form input focus outline (if added)
- **NOT** reserved for: All interactive elements, all links, hover states (use subtle color shifts instead)

### Vacation Pay Breakdown (Home Screen, per D-V08 & D-V12)

| Element | Copy |
|---------|------|
| Breakdown label (when vacation on next payment) | Состав выплаты: |
| Vacation pay row | Отпускные |

| Total row | **Итого** |

**Rationale:**
- "Отпуск" is the standard Russian term for vacation/leave.
- "Дата начала" and "Дата окончания" are clear, formal labels matching Phase 1–2 terminology.
- "Отпускные" is the legally correct Russian term for vacation pay under ст.139 ТК РФ.
- D-V12 caption is explicit and honest about scope ("этот расчёт не учитывает…"), avoiding user frustration when calculating a complex real case.
- All copy avoids vague modal/confirmation dialogs; inline errors and hints are preferred.

### Destructive Confirmation (Vacation Deletion, D-V10 Implementation)

**Delete vacation confirmation flow:**

1. User clicks "Удалить отпуск" button on a vacation dated in the future (payment date still in future).
2. Browser confirmation dialog: "Удалить отпуск с {startDate} по {endDate}?" (where dates are formatted as "день месяца" in Russian, e.g., "1 августа по 15 августа")
3. Options: "Отмена" / "Удалить отпуск"
4. If past-dated vacation (payment date already passed): Action returns error (handled server-side per D-V10) → display inline error message: "Нельзя удалять отпуска из прошлого. Вы можете изменить даты."
