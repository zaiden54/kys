## Design decision: no tracer task in this plan

`TRACER_MODE` is on for this phase, and 01-06 and 01-07 each lead with a tracer for good
reason — both establish a new pattern that everything downstream depends on. This plan does
not. Its three tasks are independent hardening edits against an architecture already proven
by the five shipped plans plus the two gap-closure plans ahead of it; there is no path to
trace and no new layer to wire. Forcing a vertical slice here would produce a fake one.

modifies.

## Design decision: the split rule is tested at the function, not through the forecast

Proving the reconciling split through `forecastNextPayment` would require forcing the next
resolved payment to be an avans in one test and a salary in another, which depends on the
real calendar date the suite happens to run on — a flaky test that would prove less. The rule
is a pure function of `(gross, kind)`, so it is exported and tested exhaustively over a parity
table. The existing DB-backed forecast tests already prove the call site is wired.
