## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Anonymous browser -> /manifest.webmanifest, /apple-icon, /api/pwa-icon | these three routes are intentionally PUBLIC/unauthenticated (a manifest and icons must be fetchable before install, i.e. before login) — no session check applies or should apply here |
| Client (navigator.standalone / matchMedia / localStorage) -> InstallBanner / login hint | purely client-side, same-origin browser API reads; no network call, no server round-trip |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-03 | Denial of Service | GET /api/pwa-icon | medium | mitigate | `size` query parameter whitelisted to exactly {192, 512} before it ever reaches `ImageResponse`'s width/height — an attacker cannot request an arbitrarily large render dimension to exhaust server CPU/memory; route.test.ts explicitly asserts an out-of-range value is clamped, not passed through. |
| T-04-04 | Tampering | Service worker (src/app/sw.ts) | medium | mitigate | `exclude: [/.*/]` in next.config.ts's Serwist config keeps the precache manifest empty — the SW can never cache (and therefore can never later serve a stale/tampered copy of) any authenticated page or API response; `scope: "/"` matches this single-origin, single-app deployment intentionally. |
| T-04-05 | Information Disclosure | InstallBanner / login re-login hint | low | accept | Both read only same-origin browser APIs (`navigator.standalone`, `matchMedia`, `localStorage`) — no PII, no third-party network call, no data leaves the device. |
| T-04-SC | Tampering | npm install (serwist, @serwist/next) | high | mitigate | 04-RESEARCH.md's Package Legitimacy Audit already lists both as OK/Approved (github.com/serwist/serwist; official Next.js PWA guide references Serwist by name as `next-pwa`'s maintained successor) — no `[ASSUMED]`/`[SUS]` disposition, so no blocking human-verify checkpoint is required; pin the exact audited versions (9.5.12) at install time. |

**Canon-referral breadcrumbs (dropped, not minted):** (1) "pass the session token through a URL/custom-scheme redirect to work around the iOS storage-jar behavior" — this is a canon OWASP sensitive-data-in-URL pattern, already explicitly rejected in this project's own PITFALLS.md as insecure; the correct behavior (a documented re-login flow) is exactly what Task 3 implements, so this is dropped rather than re-minted as a new prohibition. (2) generic "manifest/service-worker file tampering in transit" — canon (mitigated by HTTPS-only serving, which Vercel provides by default for this deployment) — dropped.
