<objective>
Fix SEC-04: replace the single static `BETTER_AUTH_URL` Better Auth previously read (`src/lib/auth.ts:18`, `baseURL: env.BETTER_AUTH_URL`) with a dynamic, request-resolved `baseURL` validated against an explicit host allowlist — so the same deployed build works correctly on localhost, every Vercel PR-preview, the new persistent `staging` branch alias, and production, without a rebuild or per-environment env-var swap, and without silently trusting an unrecognized `Host` header.

This is the phase's `tracer` — the riskiest, most novel piece of Phase 5 (multi-environment auth-origin resolution), proven end-to-end via a real automated test against the actual installed `better-auth@1.7.2` resolution functions, not a mock. Every later plan in this phase (CI, staging branch, env-var scoping) builds outward from this proven slice.

Purpose: Without this fix, staging/PR-preview login is a hard blocker per 05-RESEARCH.md's Pitfall 2 — BETTER_AUTH_URL mismatch breaks login/cookies on every environment except whichever one the static var currently points at.
Output: `src/lib/auth-allowed-hosts.ts` (new, single source of truth for trusted hosts), `src/lib/auth.ts` updated to consume it, `src/lib/auth-allowed-hosts.test.ts` (new, DB-independent proof), `src/env.ts`/`.env.example`/`README.md` updated to reflect `BETTER_AUTH_URL` is no longer read by the server.
