## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Playwright test process -> real Next.js server | Automated browser submits real credentials/PII (disposable but real email addresses) to the actual auth endpoints, same as a real user |
| e2e/fixtures.ts -> Postgres | Direct SQL delete against the `user` table, bypassing the app's own Server Action layer |
| CI/local test run -> npm registry | New `@playwright/test` devDependency install (supply-chain surface) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering (supply chain) | `@playwright/test` npm install | high | mitigate | Package-legitimacy gate + blocking human checkpoint (Task 1) before install, per the mandatory gate protocol |
| T-07-02 | Information Disclosure | Disposable test-user email/password appear in Playwright trace/screenshot artifacts on failure (`test-results/`, `playwright-report/`) | low | accept | Values are synthetic disposable credentials (never a real user's), and both artifact directories are gitignored (Task 2) so they never leave the local machine or CI runner's ephemeral filesystem |
| T-07-03 | Repudiation / Tampering | `deleteUserByEmail` issues a raw `DELETE ... WHERE email = ${email}` directly against Postgres, bypassing every application-layer authorization check | medium | mitigate | The email value is always the fixture's own freshly-generated `uniqueEmail()` output (never user input, never derived from an untrusted source), so the query can only ever delete rows this same test run created |
| T-07-04 | Elevation of Privilege | A test's disposable-account creation/cleanup logic accidentally runs against a real (non-test) `DATABASE_URL` | high | mitigate | This plan only ever runs against whatever `DATABASE_URL` the local `.env.local` already points at (the developer's own dev database, same as `npm run dev` uses today) — no new production-reachable path is introduced; Plan 07-05 is responsible for the CI-isolation guarantee (E2E-06) |

</threat_model>
