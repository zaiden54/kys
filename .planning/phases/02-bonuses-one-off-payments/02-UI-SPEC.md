## Spacing Scale

Declared values (multiples of 4px, following 8-point grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline padding |
| sm | 8px | Compact element spacing, field groups |
| md | 16px | Default element spacing, section padding |
| lg | 24px | Section padding, card gaps |
| xl | 32px | Layout gaps, page-level spacing |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical spacing |

**Tailwind utility mapping:**
- `gap-1` → 4px, `gap-2` → 8px, `gap-3` → 12px, `gap-4` → 16px
- `p-2` → 8px, `p-3` → 12px, `p-4` → 16px, `p-6` → 24px
- `mt-4` → 16px, `mt-6` → 24px

**Exceptions:** None — all Phase 1 and Phase 2 components adhere strictly to 4px multiples.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 14px (text-sm) | 500 (medium) | 1.5 |
| Heading | 18px (text-lg) | 600 (semibold) | 1.2 |
| Display | 24–32px (text-2xl, text-3xl) | 600 (semibold) | 1.2 |

**Tailwind classes:**
- Body: `text-sm` (14px), no explicit font-weight → 400 (regular)
- Label: `text-sm font-medium` → 14px, 500 weight
- Heading: `text-lg font-semibold` → 18px, 600 weight
- Display: `text-2xl font-semibold` (24px) or `text-3xl font-semibold` (32px), 600 weight

**Rationale:**
- 14px body is readable on mobile (Phase 1 requirement: PWA on iPhone).
- 1.5 line-height on body ensures readability; 1.2 on headings matches Russian typography conventions.
- Semibold (600) used for all interactive labels and headings to create clear visual hierarchy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | white (#ffffff) light / #0a0a0a dark | Page background, card backgrounds (light/dark mode toggle via `prefers-color-scheme`) |
| Secondary (30%) | zinc-100 light / zinc-900 dark | Card borders, disabled states, secondary text |
| Accent (10%) | zinc-900 (actions) / red-600 (destructive) | Primary CTA buttons, form labels, destructive actions only |
| Destructive | red-600 | Error messages, delete confirmations, validation feedback |
| Supporting | zinc-400, zinc-500, zinc-600 | Secondary text, hints, disabled states |

**Color-specific rules:**

1. **Primary CTA (Add Bonus button):** `bg-zinc-900 text-white rounded-lg px-4 py-2 text-sm font-medium` — matches Phase 1 "Перейти к настройке" button.
2. **Secondary/Cancel button:** `border border-zinc-300 text-zinc-900 rounded-lg px-4 py-2 text-sm font-medium` — outlined style.
3. **Destructive button (Delete):** `bg-red-600 text-white rounded-lg px-4 py-2 text-sm font-medium` — only for delete actions, requires confirmation.
4. **Form labels:** `text-sm font-medium` in zinc-900 (light) / zinc-100 (dark).
5. **Form inputs:** `rounded border border-zinc-300 px-3 py-2` — matches Phase 1 salary form.
6. **Error text:** `text-sm text-red-600` — matches Phase 1 validation errors.
7. **Placeholder/hint text:** `text-sm text-zinc-500` or `text-xs text-zinc-400`.
8. **Card border:** `border border-zinc-200` (light) / `border-zinc-800` (dark).
9. **Section divider:** `border-t border-zinc-200` or `border-b border-zinc-200`.

**Dark mode support:**
- Light mode: CSS `@media (prefers-color-scheme: light)` (default in globals.css)
- Dark mode: CSS `@media (prefers-color-scheme: dark)` (default applies dark values)
- No forced dark mode; iOS Safari respects system setting.

**Accent reserved for:**
- Primary CTA buttons ("Добавить бонус", "Сохранить", "Подтвердить")
- Form field labels (required/descriptive text)
- Active form input focus outline (if added)
- **NOT** reserved for: All interactive elements, all links, hover states (use subtle color shifts instead)

**Rationale:**
- "Бонус или компенсация" is a gender-neutral, natural phrasing in Russian for "bonus or compensation."
- "Состав выплаты" (composition of payment) is clear and aligns with accounting terminology.
- All copy is action-oriented and specific, never vague ("Попробуйте ещё раз" is preferred over "Ошибка").

### Destructive Confirmation (D-B06 Implementation)

**Delete bonus confirmation flow:**

1. User clicks "Удалить" button on a bonus dated in the future.
2. Browser confirmation dialog (or inline modal — TBD by planner): "Удалить бонус на сумму {amount} ₽ от {date}?"
3. Options: "Отмена" / "Удалить"
4. If past-dated bonus: Action returns error (handled server-side per D-B06) → display inline error message: "Нельзя удалять бонусы из прошлого. Вы можете изменить сумму."

### Covered States

#### 1. Bonus Input Form

**Element type:** `form`

| Category | Consideration | Status | Resolution |
|----------|---|--------|-----------|
| empty | Form on initial load | ✅ covered | Form loads with empty fields (amount, date, note). Date field defaults to today (Moscow time). Amount field shows placeholder "Например, 10000". Note field is optional and empty. |
| error | Validation errors after submit | ✅ covered | On validation failure (amount ≤ 0, invalid date format), form displays inline field-level errors using `text-sm text-red-600` below each field. No form submit until errors clear. Server-side Zod re-validation gates all mutations. |
| loading | Form submission in-flight | ✅ covered | Primary CTA text changes from "Сохранить бонус" to "Сохранение…". Button is disabled (`:disabled` state with reduced opacity). User cannot re-submit while loading. |
| partial | Form with some fields filled | ✅ covered | Form remembers user input as they type. If user fills amount and date but leaves note empty, form submits (note is optional per D-B08). Partial form state is displayed as-is without hiding or truncating fields. |
| long-text | Note field with unusually long text | 🧪 backstop | Note field truncates with ellipsis (`text-ellipsis` via Tailwind) if text exceeds container width. On focus, full text is visible. Full text is always stored and displayed in bonus list view. |

#### 2. Bonus List / History

**Element type:** `list-collection`

| Category | Consideration | Status | Resolution |
|----------|---|--------|-----------|
| empty | Zero bonuses in history | ✅ covered | Page displays centered empty-state card with heading "Нет бонусов", body copy (see Copywriting Contract), and "Добавить бонус" CTA button. Card has same styling as home screen empty states (centered, `text-center`, gap-3 layout). |
| loading | List loading in-flight | ✅ covered | Page displays skeleton (or spinner + "Загрузка бонусов…" text). Skeleton shows N placeholder rows (~3–5 rows) with shimmer effect (CSS `animation: pulse`). On data loaded, skeleton is replaced with actual list. |
| error | Load or list fetch failed | ✅ covered | Page displays error card: heading "Не удалось загрузить список бонусов", body text "Попробуйте ещё раз", and retry button. Card uses red-600 border or text to signal error state. |
| populated | Normal list with items | ✅ covered | List displays as a table or card-grid with columns: Date, Amount, Note (optional), Actions. Each row shows one bonus entry. Rows are separated by `border-b border-zinc-200`. Alternating row background color is NOT used (keep white/light bg consistent). |
| zero-one-many | List at 0, 1, N items | ✅ covered | 0 items: empty-state card (see above). 1 item: list displays single row with same styling. N items (N ≥ 2): list displays all rows, scrollable if needed. Column headers remain sticky at top (TBD by planner: `sticky top-0 bg-white` or `position: sticky`). Copy never uses singular/plural variants; all labels are plural ("История бонусов", "Бонусы" column header). |
| overflow | List scrolls if too tall | ✅ covered | On mobile/small screens, list scrolls vertically. On desktop, list may scroll or paginate (TBD by planner). No horizontal scroll (columns are narrow enough to fit 320px min width). Column headers remain visible on scroll. |

#### 3. Bonus Edit / Delete Actions
