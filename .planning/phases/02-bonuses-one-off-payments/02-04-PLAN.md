<objective>
**As a** signed-in user, **I want to** cancel or reopen an edit to one of my saved bonuses and always see the bonus's real current data, **so that** I never accidentally resubmit a stale, previously-typed value and silently overwrite a correct saved amount — closing 02-VERIFICATION.md's sole remaining CRITICAL gap (CR-01) before Phase 2 can be marked complete.

Purpose: `BonusRow`'s edit form (`src/app/(app)/bonuses/bonus-row.tsx`) captures React Hook Form `defaultValues` once at mount and never resyncs them. Because `<BonusRow key={row.id} bonus={row} />` (`page.tsx:26`) keys only on the bonus id, the same mounted form instance persists across every prop update for that row. Two concrete, reproducible failure paths follow: (1) clicking "Отмена" discards nothing — it only hides the form (`setMode("display")`), so reopening edit mode shows whatever the user last typed and abandoned, not the bonus's true saved value; (2) if this bonus is edited from another device (the app's stated cross-device cloud-sync scenario) and this row's data revalidates while still mounted, reopening edit mode still shows the value captured at first mount — resubmitting silently overwrites the newer value with the stale one. This is a direct data-loss risk on financial data, is this phase's sole open CRITICAL finding (02-REVIEW.md CR-01), and blocks 02-VERIFICATION.md truths 11 and 12 (BON-01's edit flow / D-B04's forward-recompute guarantee).

Output: `bonus-row.tsx` fixed so the edit form is always provably in sync with the bonus's real data on both failure paths, backed by a new render-based regression test (the existing `bonus-row.test.ts` is AST-only and structurally cannot catch this class of bug), plus the trivial IN-01 delete-confirm formatting inconsistency bundled in alongside since it's a one-line fix in the same file.
</objective>
