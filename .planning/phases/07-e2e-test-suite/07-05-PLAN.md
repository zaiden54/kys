## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| GitHub Actions runner -> Neon Management API | The `e2e` job authenticates with `NEON_API_KEY` to create/delete real database branches |
| GitHub Actions runner -> fresh Neon branch's Postgres | The CI-built app connects to a branch that (via copy-on-write) may inherit whatever data exists on the project's default branch at fork time |
| npm registry -> CI runner | `npx playwright install --with-deps` and `npx @playwright/mcp@latest` both fetch code at runtime from the npm/Playwright CDN |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08 | Information Disclosure | `NEON_API_KEY` / `NEON_PROJECT_ID` exposure via CI logs | high | mitigate | Stored exclusively as GitHub Actions encrypted repository secrets, referenced only via `${{ secrets.* }}`; `e2e/global-setup.ts`/`global-teardown.ts` never `console.log` the raw API key, the full connection URI, or the response body of any Neon API call — only non-secret fields (branch id, boolean success) are logged |
| T-07-09 | Elevation of Privilege | A CI-created branch's connection string, if ever accidentally logged, would grant a temporary but real write path into a database that shares the project's account | high | mitigate | Same logging discipline as T-07-08; the branch itself is deleted at the end of every run (Task 1's globalTeardown) regardless of pass/fail, bounding the exposure window to a single job's runtime even in the worst case |
| T-07-10 | Denial of Service (cost) | A compromised or forked-repo PR could trigger unlimited `e2e` job runs, each creating a billed Neon branch | medium | accept | GitHub Actions does not expose repository secrets to workflows triggered by a pull_request from a forked repository by default (GitHub's own fork-PR secret redaction) — this repo has not changed that default; `needs: ci` also means a trivially-broken/spam PR never reaches the branch-creation step at all |
| T-07-11 | Tampering (supply chain) | `npx playwright install --with-deps` / `npx @playwright/mcp@latest` fetch and execute code at CI/dev-tool runtime rather than at a pinned `npm ci` install step | medium | mitigate | `@playwright/test`'s own version is already pinned (`1.62.1`, gated by Task 1 of Plan 07-01's package-legitimacy checkpoint) and `playwright install` only downloads that same version's matching browser binaries from Microsoft's official CDN; `@playwright/mcp@latest` is a deliberate, CONTEXT.md-locked exception (dev-tool only, never part of the CI test run itself, never installed as a project dependency) — accepted here as a documented, scoped exception rather than silently unflagged |
